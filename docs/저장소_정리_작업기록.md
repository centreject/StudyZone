- 커밋은 `cfa0604 Initial commit for StudyZone portfolio repository` 하나뿐이었습니다.

- 루트에 문서 45개가 섞여 있었고, `소웨공 팀플 제작용 전체 파일/` 아래에 이미지·HTML·PDF가 여러 하위 폴더로 흩어져 있었습니다.
- 같은 문서가 여러 위치에 사본으로 존재했습니다. 예: `소웨공 제출과제/`, `(1)` 사본.

### 2.2 작업 시점을 알아낸 방법
clone한 파일은 수정 시각이 모두 clone 시점으로 같아지므로 쓸 수 없습니다. 대신 **파일 안에 남아 있는 시각 정보**를 추출했습니다.

| 파일 종류 | 사용한 정보 |
|---|---|
| `.docx`, `.xlsx`, `.pptx` | 문서 속성(`docProps/core.xml`)의 작성·수정 시각 (UTC → KST로 변환) |
| `.pdf` | `/CreationDate`, `/ModDate` |
| 캡처 이미지 | 파일명의 시각 (예: `캡처_2025_12_05_23_46_…`) |
| AI 생성 이미지 | 파일명의 시각 (예: `ChatGPT Image 2025년 12월 3일 오후 08_21_…`) |
| `.pptx` 중 문서 속성이 없는 파일 | zip 내부 항목 시각 (2025-12-24 22:18) |

시각 정보가 없는 파일(목업 이미지, drawio, manim 코드, HTML 등)은 앞뒤 결과물을 기준으로 날짜를 추정했습니다. 해당 커밋 메시지에는 `(날짜 추정)`이라고 적었습니다.

## 4. 중복 파일 처리

### 4.1 판단 기준 (요청 2에 대한 답)
**파일 내용이 바이트 단위까지 완전히 같은 경우에만** 중복으로 처리했습니다. 이름이 같은지는 기준이 아닙니다.

1. 분석 단계에서 모든 파일의 **MD5 해시**를 계산했고, 해시가 같은 파일끼리만 중복으로 분류했습니다.
2. 이력을 만들 때 스크립트가 뺄 파일마다 **Git blob 해시**를 다시 비교했습니다. 같은 내용의 파일이 남아 있지 않으면 중단하도록 했고, 17개 모두 통과했습니다.
3. 파일 시스템의 수정 시각은 비교하지 않았습니다. Git이 이 정보를 저장하지 않아서 원래 저장소에도 없었습니다.
