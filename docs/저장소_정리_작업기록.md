- 같은 문서가 여러 위치에 사본으로 존재했습니다. 예: `소웨공 제출과제/`, `(1)` 사본.

### 2.2 작업 시점을 알아낸 방법
clone한 파일은 수정 시각이 모두 clone 시점으로 같아지므로 쓸 수 없습니다. 대신 **파일 안에 남아 있는 시각 정보**를 모았습니다.

| 근거 종류 | 내용 | 시간대 처리 |
|---|---|---|
| Office 문서 속성 | `.docx`/`.xlsx`/`.pptx`의 `docProps/core.xml` 작성·수정 시각 | UTC(`Z`) → KST(+9시간) |
| PDF 생성일 | `/CreationDate`, `/ModDate` | `+09'00'`은 그대로, `Z`는 +9시간 |
| 이미지 XMP | Gemini 생성 이미지 등의 생성 시각 | UTC → KST |
| 파일명 | `캡처_2025_12_05_23_46_…`, `ChatGPT Image 2025년 12월 3일 오후 08_21_…` | 그대로(KST) |
| 디스코드 캡처 속 메시지 시각 | 캡처 이미지에 찍힌 "2025-11-16 오후 4:54" 등 | 그대로(KST) |
| 디스코드 첨부파일 ID | HTML에 남은 첨부파일 URL의 ID(스노플레이크)에서 업로드 시각 계산 | UTC → KST |
| 브라우저 확장 흔적 | HTML에 남은 AdGuard 스크립트의 `ts=` 값(파일을 연 시각) | UTC → KST |
| 화면 속 표기 | 목업 이미지에 적힌 "2025. 11. 16. 20:30 수정", 예시 데이터의 날짜 | 간접 근거 |
| drawio 저장 버전 | `<mxfile version="28.2.x">` (버전 번호로 저장 순서 비교) | 순서 판단용 |

근거가 간접적인 커밋에는 메시지에 `(날짜 추정)`과 추정 이유를 적었습니다. 모든 커밋 메시지에 날짜의 근거가 들어 있습니다.

## 4. 중복 파일 처리

### 4.1 판단 기준 (요청 2에 대한 답)
**파일 내용이 바이트 단위까지 완전히 같은 경우에만** 중복으로 처리했습니다. 이름이 같은지는 기준이 아닙니다.

1. 분석 단계에서 모든 파일의 **MD5 해시**를 계산했고, 해시가 같은 파일끼리만 중복으로 분류했습니다.
